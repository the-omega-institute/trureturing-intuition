# Formalization worth gate

The gate separates CMA analysis from permission to spend formalization resources.

```text
Pages request
-> CMA evidence
-> deterministic Intuition policy
-> accept | needs-clarification | defer | duplicate | reject
-> explicit human approval
-> Formalize
```

The gate checks exact request and release binding, contribution-route authorization, duplicate search, verification plan, falsifier, optional Topology counterfactual, novelty, structural leverage, verification cost, uncertainty, scope, and privacy.

The result carries a value vector. It has no scalar worth score. An `accept` result permits one bounded attempt and does not establish mathematical truth.

Both contribution routes are represented explicitly:

- `github-user` preserves the identity authenticated by the CMA gateway;
- `anonymous-service` uses the TrueTurning service publisher while retaining anonymous provenance.

## Authority boundary

CMA produces typed evidence. Intuition applies the deterministic policy. The user separately approves an accepted attempt. Formalize owns execution. Protected Base admission and a later truth release remain the mathematical certification boundary.
